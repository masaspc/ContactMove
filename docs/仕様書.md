# iOS 電話帳移行アプリ 詳細仕様書

- 文書バージョン: 1.0
- 作成日: 2026-07-02
- 対象OS: iOS 16.0 以上(推奨ターゲット: iOS 17+)
- 開発言語/UI: Swift 5.10+ / SwiftUI
- 対象デバイス: iPhone(iPad は Universal 対応を将来検討)

---

## 1. ユースケース整理

### 1.1 アクター

| アクター | 説明 |
|---|---|
| 送信側ユーザー | 旧端末から連絡先を送り出す人 |
| 受信側ユーザー | 新端末で連絡先を受け取る人(送信側と同一人物の場合が多い) |
| CSV利用ユーザー | Excel/Googleコンタクト/他社携帯のCSVを持ち込む人、またはバックアップとして書き出す人 |

### 1.2 ユースケース一覧

| ID | ユースケース | 概要 | 優先度 |
|---|---|---|---|
| UC-01 | 端末間ダイレクト移行(近接無線) | 旧iPhone→新iPhoneへ、両端末に本アプリを入れて近接無線で全件/選択転送 | 高 |
| UC-02 | CSVエクスポート | 連絡先をCSVファイルに書き出し、Files/クラウド/AirDropへ保存 | 高 |
| UC-03 | CSVインポート | Files等から選んだCSVを解析し、プレビュー→連絡先へ登録 | 高 |
| UC-04 | 他社形式CSVの取り込み | Googleコンタクト形式、Outlook形式、国内キャリア形式のカラムマッピング | 中 |
| UC-05 | 重複検出・統合 | インポート時/手動実行時に重複を検出し、統合方針を選んで解消 | 高 |
| UC-06 | 選択転送 | グループ/検索/チェックボックスで対象を絞って転送・書き出し | 中 |
| UC-07 | 転送履歴・結果確認 | 何件成功/スキップ/失敗したかのレポート表示 | 中 |
| UC-08 | vCardエクスポート/インポート | .vcf での入出力(CSVより情報欠落が少ない補助経路) | 中 |
| UC-09 | Android等からの受け入れ | Android側で書き出したCSV/vCFをクラウドやケーブル経由で受け取り UC-03 で取り込む | 中 |

### 1.3 代表シナリオ(UC-01)

1. 両端末で本アプリを起動し、片方が「送信」、もう片方が「受信」を選択
2. 近接無線で相手端末を発見し、両画面に同じ確認コード(4桁)を表示
3. 双方がコードを確認して承認
4. 送信側で対象連絡先を選択(既定: 全件)し転送開始
5. 進捗バー表示 → 受信側で重複チェック → 結果レポート表示

## 2. 機能要件・非機能要件

### 2.1 機能要件

| ID | 要件 |
|---|---|
| FR-01 | 連絡先の読み取り(氏名、ふりがな、電話、メール、住所、組織、誕生日、URL、メモ※、画像) |
| FR-02 | 連絡先の新規作成・更新(統合時) |
| FR-03 | 近接無線(MultipeerConnectivity)による端末間転送(暗号化必須) |
| FR-04 | BLE(CoreBluetooth)によるフォールバック転送(Wi-Fi/MPCが使えない環境向け・任意実装) |
| FR-05 | CSVエクスポート(UTF-8 BOM付き、RFC 4180準拠) |
| FR-06 | CSVインポート(文字コード自動判定: UTF-8/Shift_JIS、カラムマッピングUI付き) |
| FR-07 | vCard 3.0 の入出力 |
| FR-08 | 重複検出(電話番号正規化一致/メール一致/氏名+補助キー一致) |
| FR-09 | 統合戦略の選択(スキップ/上書き/フィールド単位マージ/両方残す) |
| FR-10 | インポート前プレビュー(件数、新規/重複内訳、サンプル表示) |
| FR-11 | 転送結果レポート(成功/スキップ/失敗、失敗理由) |
| FR-12 | 選択転送(全件/グループ/検索絞り込み/個別チェック) |
| FR-13 | 処理のキャンセルと安全な中断(部分コミットの扱いを明示) |

※メモ(note)フィールドは Apple の特別な Entitlement 承認が必要(§7.4)。MVPでは対象外。

### 2.2 非機能要件

| 分類 | 要件 |
|---|---|
| 性能 | 5,000件の読み取り+CSV生成を10秒以内(A15世代基準)。MPC転送は1,000件(画像なし)を30秒以内目標 |
| 容量 | 連絡先画像は既定で縮小(長辺512px, JPEG 0.7)して転送。原寸転送はオプション |
| 信頼性 | 転送はチャンク+チェックサム(SHA-256)で検証。失敗チャンクは再送 |
| 中断耐性 | インポートはトランザクション単位(CNSaveRequestを100件単位でバッチ)。中断時は完了バッチまで確定し件数を報告 |
| セキュリティ | 連絡先データを外部サーバへ送信しない(完全ローカル/P2P)。P2Pは暗号化必須+確認コード照合 |
| プライバシー | 収集ゼロ。解析SDK・広告SDKなし。App Privacy「データ収集なし」申告 |
| アクセシビリティ | Dynamic Type、VoiceOver ラベル対応 |
| 多言語 | 日本語/英語(String Catalog) |
| オフライン | 全機能がネット接続なしで動作 |

## 3. iOSで実現可能な方式と制約

| 方式 | 可否 | 説明 |
|---|---|---|
| Contacts framework (CNContactStore) | ◎ | 読み書きの正規手段。ユーザー許可必須 |
| iOS 18+ の限定アクセス(Limited Access) | 要対応 | ユーザーが「一部の連絡先のみ」を選べる。`.limited` 状態のハンドリング必須 |
| MultipeerConnectivity (MPC) | ◎ | Wi-Fi/ピアツーピアWi-Fi/Bluetooth を自動選択する近接通信。端末間転送の本命 |
| CoreBluetooth (BLE GATT / L2CAP) | ○ | 実装可能だが低速・実装コスト大。フォールバック用 |
| Bluetooth Classic (PBAP/OPP) | × | サードパーティ非公開(§4.1) |
| AirDrop (vCard共有) | ○ | UIActivityViewController 経由。「アプリ外の標準経路」として案内可能 |
| Files / Document Picker | ◎ | CSV/vCF の入出力。`.fileImporter` / `.fileExporter` |
| iCloud同期の代替 | 注意 | Appleの標準移行(クイックスタート/iCloud)が最有力な競合。アプリの価値は「CSV対応」「選択転送」「重複統合」「Android連携」に置く |

**主要制約まとめ**

- 連絡先の note フィールドは Entitlement 申請が必要(承認制)
- iOS 18 の限定アクセスでは全件移行ができない場合がある → 設定誘導UIが必要
- バックグラウンドでの長時間P2P転送は不可(MPCはフォアグラウンド前提。転送中は画面ロック防止 `isIdleTimerDisabled` を検討)
- 相手端末にアプリが入っていない限り、無線で他端末の電話帳を「吸い出す」ことは一切不可能

## 4. Bluetooth方式の実装可否と代替案

### 4.1 できないこと(理由付き)

| やりたいこと | 可否 | 理由 |
|---|---|---|
| 旧端末(アプリなし)の電話帳をBluetoothで取得 | **不可** | カーナビ等が使う PBAP(Phone Book Access Profile)は iOS ではサードパーティアプリに開放されていない。Bluetooth Classic のプロファイルは MFi 認定アクセサリ(ExternalAccessory)専用 |
| OPP(Object Push)でvCard受信 | **不可** | 同上。iOS は OPP 自体を標準サポートしない |
| ペアリング画面をアプリから直接開く/自動ペアリング | **不可** | API 非公開 |
| バックグラウンドで大容量BLE転送 | **実質不可** | BLEバックグラウンドは制約が多く、数MB級の転送は非現実的 |

### 4.2 できること

| 方式 | 特徴 |
|---|---|
| **MultipeerConnectivity(推奨・第一候補)** | 「Bluetooth経由」というユーザー要望の実質的な回答。Bluetooth/ピアツーピアWi-Fiを内部で自動選択し、暗号化(`.required`)対応。数千件+画像でも実用速度。実装が最も簡単 |
| **CoreBluetooth GATT(第二候補)** | 自前サービスUUIDで Central/Peripheral を実装。MTU ~185〜512B、実効数KB/s。テキストのみ1,000件なら現実的だが画像は厳しい |
| **CoreBluetooth L2CAP チャネル(iOS 11+)** | GATTより高速(数十KB/s〜)。ストリーム実装が必要で工数大。BLEフォールバックを本気でやる場合の選択肢 |
| **AirDrop(補助)** | vCardを共有シートから送る標準機能。アプリなしの相手にも渡せる唯一の無線経路として案内 |

### 4.3 採用方針

1. **MVP: MultipeerConnectivity のみ実装**(UI上の表記は「近くの端末に転送(Bluetooth/Wi-Fi)」とし、技術的に正確かつユーザー期待に沿う)
2. Phase 2 で BLE L2CAP フォールバックを検討(Wi-Fi/Bluetooth両方OFFの環境は稀なため優先度低)
3. 「アプリを入れられない相手」には vCard + AirDrop / CSV + クラウド共有を案内する導線を用意

### 4.4 転送プロトコル(MPC上のアプリケーション層)

```
1. Handshake     : {protocolVersion, deviceName, totalCount, totalBytes, includesPhotos}
2. Verification  : 4桁コードを乱数生成し双方表示 → 双方が承認ボタン
3. Data          : ContactPacket をチャンク送信
                   ContactPacket = JSON(連絡先配列, 最大100件/チャンク) + 画像は別ストリーム
4. Ack           : チャンクごとに {chunkIndex, sha256} を返送。不一致は再送(最大3回)
5. Complete      : {receivedCount, mergedCount, skippedCount} を送信側へ返し双方でレポート表示
```

- ペイロードは Codable な中間モデル(§9 `TransferContact`)を JSON エンコード + zlib 圧縮
- `MCSession(encryptionPreference: .required)` を必須とする

## 5. CSVインポート/エクスポート仕様

### 5.1 エクスポート仕様

- 文字コード: **UTF-8(BOM付き)** … Excel(日本語環境)で文字化けさせないため
- 改行: CRLF、区切り: カンマ、引用: RFC 4180 準拠(フィールド内のカンマ/改行/`"` はダブルクォート囲み、`"` は `""` にエスケープ)
- 複数値(電話・メール等)は **列を分ける方式**(電話1/電話1ラベル/電話2/…最大3、あふれた分は「電話その他」にセミコロン連結)
- 画像はCSVに含めない(vCardエクスポートを案内)

**標準カラム(v1)**

```
姓,名,姓ふりがな,名ふりがな,ミドルネーム,敬称(前),敬称(後),
会社名,部署,役職,
電話1,電話1ラベル,電話2,電話2ラベル,電話3,電話3ラベル,電話その他,
メール1,メール1ラベル,メール2,メール2ラベル,メールその他,
郵便番号,都道府県,市区町村,番地,建物名,国,住所ラベル,
URL,誕生日(YYYY-MM-DD),グループ
```

- ラベル値: `自宅` / `勤務先` / `携帯` / `iPhone` / `メイン` / `その他`(CNLabel との相互変換表を内部に持つ)
- ファイル名: `連絡先_YYYYMMDD_HHmm.csv`

### 5.2 インポート仕様

1. `.fileImporter` で CSV/vCF を選択(UTType: `.commaSeparatedText`, `.vCard`, `.plainText`)
2. **文字コード判定**: BOM → UTF-8 試行 → 失敗時 Shift_JIS → 失敗時 EUC-JP → 全滅ならエラー表示
3. **形式判定**: ヘッダー行を既知プリセットと照合
   - 本アプリ標準 / Google Contacts(`Name,Given Name,...`)/ Outlook(`First Name,Middle Name,...`)/ 汎用
4. 判定できない列は **カラムマッピングUI** でユーザーが割り当て(「この列=電話番号」等)。マッピングはプリセットとして保存可能
5. **バリデーション**: 氏名・電話・メールが全て空の行はスキップ。電話番号は数字/`+`/`-`/`()`/空白以外を除去。不正誕生日は無視して他フィールドのみ取り込み
6. **プレビュー画面**: 総行数 / 取り込み対象 / 重複見込み / エラー行(行番号+理由) / 先頭20件のサンプル
7. 取り込み実行(§6 の統合ロジック経由)→ 結果レポート

### 5.3 エラーハンドリング

| ケース | 挙動 |
|---|---|
| 列数不一致の行 | 行スキップ+レポートに行番号記載 |
| 100MB超のファイル | 事前に拒否(メッセージ表示) |
| 0件 | 「取り込める行がありません」+ 想定原因(文字コード/ヘッダー)を提示 |
| 途中失敗 | 完了済みバッチまで確定し「N件まで取り込み済み」を明示 |

## 6. 連絡先重複統合ロジック

### 6.1 正規化

- **電話番号**: 記号除去 → 日本番号は E.164 化(`090…` → `+8190…`)。国番号不明時は国内番号として扱い、比較は「E.164一致 or 下10桁一致」
- **メール**: 小文字化、前後空白除去
- **氏名**: NFKC正規化、全半角統一、前後空白除去。ふりがなはカタカナに統一して比較補助に使用

### 6.2 マッチング判定(段階式)

| レベル | 条件 | 判定 |
|---|---|---|
| L1 | 正規化電話番号が1つでも一致 | 重複(確度: 高) |
| L2 | 正規化メールが1つでも一致 | 重複(確度: 高) |
| L3 | 姓名完全一致 かつ (組織一致 or ふりがな一致 or 誕生日一致) | 重複(確度: 中) |
| L4 | 姓名完全一致のみ | **候補**(自動統合しない。確認リストに出す) |

### 6.3 統合戦略(ユーザー選択)

| 戦略 | 動作 |
|---|---|
| スキップ(既定) | 既存を変更せず、重複した取り込み行を捨てる |
| マージ(推奨表示) | 既存レコードに「新規側にしかない値」を追加。同ラベル同値は重複追加しない。氏名等の単一値フィールドは既存優先(空なら新規側を採用) |
| 上書き | 新規側の値でフィールドを置換(新規側が空のフィールドは既存維持) |
| 両方残す | 無条件で新規作成 |

- L4(候補)は一覧画面で1件ずつ「統合する/しない」を選択(全選択/全解除あり)
- 既存端末内の重複掃除(スタンドアロン機能)も同エンジンを使用: 全件を L1〜L3 でグルーピング → グループごとにマージプレビュー → 実行

### 6.4 マージの実装単位

- `CNMutableContact` に対しフィールドごとに適用 → `CNSaveRequest.update(_:)`
- 100件単位でバッチ実行、各バッチ成功時に進捗更新
- 実行前に「変更内容の要約(M件をマージ、N件を新規作成)」を必ず表示

## 7. 権限・プライバシー設計

### 7.1 権限一覧

| 権限 | 用途 | 取得タイミング |
|---|---|---|
| 連絡先 (`NSContactsUsageDescription`) | 読み書き | 初回の「エクスポート/転送/インポート実行」直前(起動時に取らない) |
| ローカルネットワーク (`NSLocalNetworkUsageDescription` + `NSBonjourServices`) | MPC転送 | 転送画面を開いた時にOSが自動表示 |
| Bluetooth (`NSBluetoothAlwaysUsageDescription`) | MPC/BLE | 同上 |

### 7.2 iOS 18 限定アクセス対応

- `CNAuthorizationStatus` が `.limited` の場合:
  - バナーで「一部の連絡先のみアクセス許可中(N件)。全件移行するには設定で『フルアクセス』に変更してください」と表示
  - 設定アプリへのディープリンクボタンを設置
  - 限定のままでも許可された範囲で機能は動作させる

### 7.3 プライバシー方針

- 外部送信ゼロ: サーバー・解析・広告SDKなし。P2Pは端末間直接通信のみ
- 中間ファイル(転送用一時JSON等)は `tmp/` に置き、完了/失敗時に即削除
- エクスポートCSVの保存先はユーザー指定のみ(アプリが勝手にクラウドへ置かない)
- App Store の App Privacy: 「データを収集しません」
- 初回起動時に上記方針を1画面で明示(同意ボタン)

### 7.4 note フィールドの制約

- `CNContactNoteKey` の読み書きには `com.apple.developer.contacts.notes` Entitlement が必要で、Apple への申請・承認が前提
- **MVPではメモ非対応**とし、仕様書・アプリ内ヘルプに明記。承認取得後に Phase 2 で対応

## 9. データモデル

### 9.1 中間モデル(転送・CSV共通)

```swift
struct TransferContact: Codable, Identifiable, Hashable {
    var id: UUID = UUID()               // アプリ内一時ID(CNContact.identifierとは別)
    var givenName: String
    var familyName: String
    var middleName: String?
    var phoneticGivenName: String?
    var phoneticFamilyName: String?
    var namePrefix: String?
    var nameSuffix: String?
    var organizationName: String?
    var departmentName: String?
    var jobTitle: String?
    var phones: [LabeledValue]          // label: home/work/mobile/iPhone/main/other
    var emails: [LabeledValue]
    var postalAddresses: [PostalAddress]
    var urls: [LabeledValue]
    var birthday: DateComponents?
    var imageData: Data?                // 縮小済みJPEG(設定に依存)
    var groups: [String]

    struct LabeledValue: Codable, Hashable {
        var label: ContactLabel
        var value: String
    }
    enum ContactLabel: String, Codable { case home, work, mobile, iPhone, main, other }

    struct PostalAddress: Codable, Hashable {
        var label: ContactLabel
        var postalCode: String?
        var state: String?      // 都道府県
        var city: String?
        var street: String?
        var subLocality: String?// 建物名相当
        var country: String?
    }
}
```

### 9.2 転送プロトコルモデル

```swift
struct TransferManifest: Codable {
    let protocolVersion: Int            // 1
    let deviceName: String
    let totalCount: Int
    let totalBytes: Int
    let includesPhotos: Bool
    let chunkCount: Int
}

struct ContactChunk: Codable {
    let index: Int
    let contacts: [TransferContact]     // 最大100件
    let sha256: String                  // 圧縮後ペイロードのハッシュ
}

struct ChunkAck: Codable {
    let index: Int
    let ok: Bool
}

struct TransferResult: Codable {
    let received: Int
    let created: Int
    let merged: Int
    let skipped: Int
    let failed: [FailedItem]
    struct FailedItem: Codable { let displayName: String; let reason: String }
}
```

### 9.3 重複判定モデル

```swift
struct DuplicateGroup: Identifiable {
    let id = UUID()
    var members: [ContactRef]           // 既存 or 取り込み中の参照
    var confidence: Confidence          // .high(L1/L2) / .medium(L3) / .candidate(L4)
    enum Confidence { case high, medium, candidate }
}

enum MergeStrategy: String, CaseIterable {
    case skip, merge, overwrite, keepBoth
}
```

### 9.4 永続化

- アプリDBは持たない(連絡先の実体は常に CNContactStore)
- 保存するのは軽量設定のみ: `UserDefaults`(既定統合戦略、画像設定)+ マッピングプリセット(JSONファイルを Application Support に保存)
- 転送履歴レポートは直近10件を JSON で保存(個人データは表示名と件数のみ)

## 10. SwiftUIでの実装方針

### 10.1 アーキテクチャ

- **MVVM + サービス層**、Swift Concurrency(async/await, AsyncStream)中心
- モジュール構成(Swift Package でローカル分割):

```
App(SwiftUI)
 ├─ Features/
 │   ├─ Home
 │   ├─ Transfer        (送受信UI)
 │   ├─ CSV             (Import/Export UI, マッピングUI)
 │   ├─ Dedupe          (重複整理UI)
 │   └─ Settings
 ├─ Core/
 │   ├─ ContactsKit     (CNContactStoreラッパ: fetch/save/権限)
 │   ├─ TransferKit     (MPCセッション, プロトコル, チャンク処理)
 │   ├─ CSVKit          (RFC4180パーサ/ライタ, 文字コード判定, プリセット)
 │   ├─ DedupeKit       (正規化, マッチング, マージ計画生成)
 │   └─ Models          (TransferContact ほか)
 └─ Tests/(各Kitに対応)
```

### 10.2 主要技術ポイント

- 権限: `CNContactStore.requestAccess` を async でラップ。`.limited` を含む状態を `@Observable` な `PermissionsModel` で全画面に配信
- 連絡先取得: `CNContactFetchRequest` を `Task.detached` でストリーム処理し、UIへは `AsyncStream` で進捗を流す
- MPC: `MCNearbyServiceAdvertiser` / `MCNearbyServiceBrowser` を actor でラップ(`TransferSession` actor)。delegate → AsyncStream 変換
- CSVパーサ: 自前実装(依存最小化)。ステートマシン方式でクォート/改行内包に対応。SPMで単体テスト可能に
- 大量データUI: プレビュー/選択リストは `LazyVStack` + ページング(200件ずつ)
- 転送中: `UIApplication.shared.isIdleTimerDisabled = true`(終了時に戻す)
- エラー設計: `enum AppError: LocalizedError` に集約し、全画面共通のエラーシート

### 10.3 使用フレームワーク

| 用途 | フレームワーク |
|---|---|
| 連絡先 | Contacts / ContactsUI(個別表示に `CNContactViewController` 流用可) |
| 転送 | MultipeerConnectivity(Phase2: CoreBluetooth) |
| ファイル | SwiftUI `.fileImporter` / `.fileExporter`, UniformTypeIdentifiers |
| 圧縮/ハッシュ | Compression(zlib), CryptoKit(SHA-256) |
| 外部依存 | なし(方針としてゼロ依存) |

## 12. MVPの開発順序

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| **P0: 基盤(1週目)** | プロジェクト雛形、モジュール分割、Models、ContactsKit(読取+権限+limited対応) | 実機で全連絡先を一覧表示できる |

| **P3: 重複エンジン(3〜4週目)** | DedupeKit、統合戦略、インポート統合フロー、候補確認UI | 冪等インポート(IT-07)が通る |
| **P4: 端末間転送(4〜6週目)** | TransferKit(MPC)、送受信UI、確認コード、チャンク/再送、レポート | 実機2台で1,000件転送成功 |

## 付録A: できないこと一覧(再掲・ユーザー説明用)

| 要望 | 回答 |
|---|---|
| アプリの入っていないガラケー/旧iPhoneからBluetoothで吸い出したい | 不可(iOSがPBAP/OPPを開放していない)。→ 旧端末側でvCard/CSVを書き出し、クラウド・AirDrop・SDカードリーダー経由で取り込む |
| 連絡先の「メモ」も移行したい | MVPでは不可(Apple承認制Entitlementが必要)。承認後に対応予定 |
| バックグラウンドで転送し続けたい | 不可。転送中は画面を開いたままにする設計 |
| iOS 18で「一部のみ許可」のまま全件移行したい | 不可。設定でフルアクセスに変更する誘導を表示 |
